# 迭代 1：登录鉴权与班级材料上传（auth-upload）

## Why（为什么做）

班级材料共享与知识库是产品的第一块地基。本迭代先解决三件事：**谁能做什么（角色权限）**、
**数据边界从哪里来（班级隔离）**、**材料如何入库（上传 + 正文提取）**。
没有可靠的入库与隔离，后续任何检索能力都会变成跨班数据泄露的通道。

## What Changes（本迭代做什么）

- 账号密码登录；角色只有**教师**与**学生**两种；身份、角色、班级全部来自**服务端会话**。
- 每个用户属于一个**固定班级**；只能访问自己班级的材料，跨班访问由服务端拒绝（404）。
- 教师可上传 `.txt` / `.md` 材料：提取正文，**在同一事务内**写入 `materials` 与 `knowledge_entries` 两表。
- 本班材料列表与详情来自**按会话班级过滤的数据库查询**；文件下载经鉴权 API，不静态暴露存储目录。
- Web 端提供登录页 + 材料页：`/api/me`、未登录 401 回登录页、正文安全渲染；可选体验增强（北大红、深浅色、列表/网格、本班搜索、命令面板、上传进度、toast、Markdown 渲染）。

## Capabilities（能力清单）

### 新增能力
- `auth-upload`：登录会话、角色权限、班级隔离、材料上传与入库、鉴权下载、Web 页面与体验增强。

## Impact（影响范围）

- 新建后端服务（Flask + SQLite），单实例单库，以 `class_id` 作多租户边界。
- 新建前端两个页面（登录页、材料页）。
- 为后续迭代的检索/问答预置 `knowledge_entries` 数据行，但**本迭代不实现检索**。

## Non-goals（明确不做项）

> 以下内容**本迭代明确不做**；即使实现了也不作为必做验收项。

- ❌ 跨班检索、向量检索、RAG 问答（本班前端筛选不算跨班检索）
- ❌ 知识库对话 / 问答接口
- ❌ 作业发布与提交
- ❌ 平台超级管理员角色（天然跨班，与"跨班返回 404"的隔离验收直接冲突，推迟到隔离验收通过后单独设计）
- ❌ 以学校 / 课程为租户（本课租户是班级）
- ❌ `.txt` / `.md` 以外的文件类型（如 docx、pdf、图片）
- ❌ 注册、找回密码、多因素认证
