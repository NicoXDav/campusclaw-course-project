# 第 2、3、4 次课：到底要做什么

核对日期：2026-09-26。来源：[课程入口](https://devops.hello1023.com/)。当前网站第2课是可翻页课件，第3、4课已呈现为多页实现教程，本说明阅读了各课入口及其所有教学子页，而不是只读首页简介。

## 一条连续的项目主线

项目是 **CampusClaw 班级教学知识库**，用户是教师和学生，数据边界是班级。不是课表网站，不是无权限的公共聊天机器人，也不是把所有学期资料一次做完。第二课中的课表仅用于说明为什么应先写规约。

| 课次 | 这一课负责什么 | 这一课的交付物 | 不应提前做的事 |
|---|---|---|---|
| 第2课 | 把需求变成可验收规约 | 同仓 README、OpenSpec proposal/design/spec/tasks，纳入Git | 不写业务代码、不Apply、不运行真实Compose，任务保持未勾选 |
| 第3课 | 按第二课规约实现迭代1 | 登录、教师/学生权限、班级隔离、txt/md上传和正文入库、Compose部署与验收 | 不做检索问答、流式对话、PDF/Word/OCR |
| 第4课 | 在迭代1基础上实现迭代2 | 可追溯检索的OpenSpec变更、切分/嵌入/向量入库、三种检索、出处、短回答 | 不做流式长对话、跨班访问、重排序和后续作业流程 |

课程首页说学期项目最终还要有大模型、智能体、知识库、技能与MCP，这些是整个学期目标，不能误解为第四课必须一次实现所有内容。

## 第二课：先把“做完”说清楚

[第2课原课件](https://devops.hello1023.com/课件/第2课-课件-SDD与CampusClaw规约/index.html)

核心是 SDD（规约驱动开发）。只给模型一句“做个系统”会导致硬编码、范围漂移和没有验收标准。因此需求必须存进开发仓库，不依赖某一段聊天记录。

四件套分别回答：

- `proposal.md`：为什么做、改什么、不做什么、影响哪些能力。
- `design.md`：技术选择、数据结构、信任边界、部署方式、取舍理由。
- `specs/<capability>/spec.md`：Requirement规定行为；每条Scenario写出WHEN输入条件和THEN可观察结果。
- `tasks.md`：按依赖顺序拆解实现任务，每项有可执行验收方式。

本课落到CampusClaw的要求是：教师/学生登录；学生不能上传；教师能上传本班材料；所有业务访问按班级隔离；材料、正文和关联关系落库；列表必须来自数据库。错误密码、未登录、非法文件、跨班访问也必须写成场景，不能只写成功流程。

README应说明价值、核心场景、明确不做项。完成Review与结构校验后，把规约提交到仓库，换一个对话仍能从文件重建需求。第二课的“全空checkbox”指当时仅完成提案阶段；后续真正实现验收后应据实勾选，不能为保持第二课截图而把第四课已完成事项都留空。

## 第三课：把权限与入库地基做实

[第3课教程](https://devops.hello1023.com/课件/第3课-课件-认证授权与知识库入库/index.html)

按先数据、再认证、再授权与隔离、再上传、最后部署验收的顺序实现。认证解决“你是谁”，授权解决“你能干什么”，班级隔离解决“你能看哪些数据”。隐藏按钮不能代替服务端拒绝请求。

需要做到：

1. 预置两个班、教师和学生，以及能区分归属的材料；密码哈希存储。
2. 登录建立服务端会话，成功登录轮换会话，过期会话失效；未知账号、错误密码与限流响应一致，耗时接近，真实原因仅记服务端日志。
3. 材料列表、详情、下载按服务端读取的class_id查询；请求体自己写class_id不生效。直接跨班访问与资源不存在同样返回404。
4. 教师上传UTF-8的txt/md文件，校验大小和内容，把文件、材料记录与知识库正文关联。两表同事务；失败不能留下孤立文件或半条记录。
5. 本班学生刷新可见新材料且只读。文件不能放在无需认证的静态目录。
6. Compose启动、健康检查、持久化卷。down后再up应保留数据；down -v是主动清空，不能用来证明持久性。
7. OpenSpec严格校验仅验证文档结构，业务是否完成要真正执行Scenario；两层都通过再考虑归档。

当前教程的参考实现为Go、Nginx、MySQL；第二课课件也给出了Flask、SQLite示例。个人已有作业使用Flask，因此本仓保留Python，存储升级为MySQL与Qdrant，差异和原因在design中明确说明。

阅读覆盖：scope、architecture、auth-schemes、security、s2-data、s4-isolation、s5-upload、s7-compose、s8-verify、think。

## 第四课：在本班查到内容，还能核验出处

[第4课教程](https://devops.hello1023.com/课件/第4课-课件-可追溯知识库检索/index.html)

本次变更名是 `add-traceable-vector-retrieval`，能力名是 `knowledge-retrieval`。登录和上传继续沿用第三课能力。

### 入库链路

上传原文 → 文档切片 → 嵌入模型生成向量 → Qdrant存向量。MySQL保留完整正文、切片文本和偏移；Qdrant只存浮点向量及关联编号。关联约定为 **point.id = knowledge_chunks.id = payload.chunk_id**，返回摘录必须回关系库读取。

三种切分：auto默认800字、80字重叠并优先在自然断点切开；custom允许100–2000字、0–50%重叠、自定义分隔符和清洗；hierarchy按Markdown一级至三级标题分章，超长再切。预处理不修改上传原文，清洗后的偏移只能指向预处理文本。变更切分策略不会自动重切历史数据，必须显式重建并清理旧切片/向量。

### 检索链路

| 模式 | 访问的组件 | 过滤与排序 |
|---|---|---|
| keyword | MySQL ngram全文索引 | 本班、ready切片、正全文分；不调用嵌入或Qdrant |
| vector | 问句嵌入 → Qdrant → MySQL回表 | Qdrant按班级过滤，余弦至少0.35，回表再次检查班级 |
| hybrid（默认） | 两路均执行 | 两路先过滤，再以RRF k=60按名次融合；不能直接加全文分与余弦分 |

每条命中应显示：材料标题、第几段、字符范围、摘录，并可打开原文。原文和索引之间的可验证关联就是“内容溯源”，仅打印一个文件名并不充分。

Qdrant故障时keyword仍能用；vector/hybrid明确503。空查询400。用A班账号搜索仅B班存在的词，不能泄露B班标题和内容；跨班检索应呈现无命中而非提示“你没权限看B班”。直接按ID访问仍为404。

### 短回答链路

`POST /api/ask` 用最新一句问题做本班混合检索、取前4条。有切片才把编号后的标题、段号、正文交给生成模型，回答中的[1]/[2]要能指回citations。无命中返回固定的“资料中未找到相关内容”，citations为空，不能调用生成模型凑答案。客户端system不能变成服务端指令。本课不做流式长会话。

阅读覆盖：rag、flow、class-scope、answer、chunk、scope、think。尤其核对了think页的5个问题：组件访问、伪造班级、无据是否生成、重建策略、关系库与向量库的形态和关联。

## 本次应交给老师什么

提交可访问的开发仓库地址，老师应能从仓库看到：

1. 第四课OpenSpec变更四件套和明确的需求/失败场景。
2. 延续第二、三课流程的实现代码及Git历史。
3. 依README可启动的Compose系统、双班验收账号配置方法。
4. 检索/溯源/权限/索引恢复等测试与真实运行证据。
5. 已完成和待外部配置事项的真实状态，不能把模拟网关测试说成真实生成模型测试。

本仓保留第四课change为active便于审阅，没有提前归档。发邮件属于之后的提交动作，待用户提供收件信息后再进行。
